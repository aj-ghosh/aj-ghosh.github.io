How to People-Proof Your Workflows

When a procedure isn’t followed, the instinct is to blame training. Send them back through it. Remind them. Document the reminder.

But most of the time, the procedure is the problem. It’s unclear, it’s hard to find, or following it takes more effort than winging it. People-proofing means designing the workflow so the right action is the easiest action.

Start with the trigger

Every workflow should begin with a specific, observable event — “new prospect inquiry,” not “whenever someone reaches out.” Vague triggers produce vague compliance. If two people can disagree about whether the workflow has started, the trigger is broken.

Name one owner

Shared ownership is no ownership. If two people are responsible, neither is — each assumes the other handled it. Every step gets exactly one name next to it.

Write for the new hire, not for yourself

If someone who’s never done the task can complete it without asking questions, the procedure works. If they can’t, rewrite the procedure — don’t retrain the person. This is the test most SOPs fail, because they’re written by experts who skip the steps that feel obvious.

Build guardrails into the system

Required fields. Checklists. Templates. Don’t rely on memory for anything that matters — memory is the least reliable system in your practice, and it’s the one most practices run on.
